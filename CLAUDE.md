# CLAUDE.md

Guidance for working in this repo. Design and roadmap: [PLAN.md](./PLAN.md). Keep this file current: when a decision is made or reversed, record it under **Decisions** with its reason.

## Commands

```sh
pnpm install
pnpm typecheck        # tsc over all packages and apps, then the ```ts examples of the root and package READMEs and of docs/guides (scripts/check-readmes.mjs)
pnpm test             # unit tests (Node): CPU references, color, float16, compare, playground logic, @rullino/node on Dawn (needs a Vulkan driver: `apt install mesa-vulkan-drivers` without a GPU)
pnpm test:browser     # GPU tests in headless Chromium (WebGPU), incl. GPU<->CPU parity (on Windows in the installed Chrome, see scripts/browser-launch.mjs)
pnpm test:all         # both
pnpm test:coverage    # both, with v8 coverage and per-area thresholds (report in coverage/index.html)
pnpm build            # builds every package into dist/ (tsc + scripts/fix-imports.mjs) and the playground (Vite)
pnpm size             # gzip sizes against size-budget.json (after build)
pnpm test:pack        # packs the packages, installs the tarballs in a temp project, runs them in Node and in Chromium (GPU)
pnpm test:e2e         # smoke-tests the built playground in headless Chromium (run after build)
pnpm test:e2e:base    # the built playground served from a sub-path, as GitHub Pages does (run after build)
pnpm test:ml          # the real SlimSAM, MI-GAN and Depth Anything models on ONNX Runtime WASM (downloads 69 MB once into .cache/models)
pnpm test:e2e:ml      # the playground's Object, Remove object and Lens blur tools with the real models (after build; models served locally)
pnpm bench            # GPU timings per filter + a chain at 1024x768 (SwiftShader numbers: compare runs, not machines)
pnpm report:parity    # how far THIS machine's GPU is from the CPU references, per filter and case (writes and prints packages/filters/report/parity-report.md; informational, never fails on numbers): run it on real hardware
pnpm bench:cpu        # CPU reference vs fast path: the PLAN chains at 12 MP (`chains --size 1155x866` for 1 MP) and every filter at 1024x768 (`filters --only <id>`)
pnpm bench:web        # comparison page (#77): rullino vs PixiJS, Photon, wasm-vips; prints a URL to open in a real browser (`--headless --strict --sizes 320x240 --runs 1` = CI smoke)
pnpm dev              # playground dev server
npx vitest run path/to/file.test.ts   # single file
npx vitest run packages/presets -u    # rewrite golden look snapshots after a deliberate recipe change
npx vitest run packages/filters -u    # rewrite docs/filters.md (filter reference) and docs/parity.md (tolerance table) after changing a filter's schema or tolerance
```

## Layout

- Every package has a public root (`src/index.ts`) and, for `core` and `ml`, an unstable `./internal` subpath (`src/internal.ts`: shader generators, uniform packing, texture caches, model I/O processing). `src/api.test.ts` pins the exact runtime export list of each root.
- `packages/core`
  - `params.ts` parameter schema (float/int/bool/enum/kernel/curve/lut/image/color, optional `unit: 'px'` and UI `group`): types, validation, defaults, `scaleParams`, uniform layout/packing, generated WGSL `Params` struct.
  - `filter.ts` / `define.ts` filter contracts and `defineFilter()`: `pointwise` (CPU reference derived from `pixel()`) and `multipass` (fixed list of passes + whole-image CPU reference).
  - `curve.ts` monotone tone curves sampled to a 256-entry LUT, CPU sampler and WGSL sampler generator.
  - `color.ts`, `oklab.ts` CPU colour maths; `wgsl.ts` the `rl_*` WGSL twins prepended to every shader.
  - `image.ts` `LinearImage`, `sampleImage` and its WGSL twin (image params); `gpu/` context, rgba16float upload/readback, `importImage` / `encodeToTexture` / `readSrgb8` (sRGB edges), area `downscale`, `runMultipass`, `runFilter` (any kind).
  - `pipeline/` `Step` chains: `fuse.ts` (namespacing + fused shader), `pipeline.ts` (cached incremental `Pipeline`), `chain.ts` (`runChainCpu` reference).
  - `resize.ts` CPU area downscale and `fitWithin`.
  - `png.ts` dependency-free PNG encoder (8/16-bit RGBA); `encode.ts` `encodeImage` (PNG / JPEG / WebP from a `LinearImage`); `gpu/export.ts` `exportImage` from a texture.
  - `mask.ts` masks (linear, radial, raster), CPU `maskValue` / `maskImage` / `blendMasked` / `resampleRaster`; `gpu/mask.ts` the WGSL twin, `blendMask` and `renderMask`; `paint.ts` `paintStroke` (brush on raster masks); `wand.ts` `magicWand`; `refine.ts` `refineMask` (guided filter).
  - `geometry.ts` `Geometry` (orientation, perspective, straighten, crop) composed into one homography, `geometryFrame`, CPU `applyGeometryCpu`; `gpu/geometry.ts` `applyGeometry`.
  - `edit.ts` `applyEdit` (document → image: geometry, steps, long-side shrink; GPU with a context, else CPU; textures it makes go back to the pool).
  - `serialize.ts` `serializeChain` / `parseChain` / `migrateChain` (edit documents: chain + geometry + output as JSON); `edit.schema.json` (package root, published as `@rullino/core/edit.schema.json`) is its JSON Schema, checked by `edit-schema.test.ts` with Ajv.
  - `lut.ts` 3D LUTs: `createLut`, `.cube` / HaldCLUT parsers, CPU trilinear sampler and its WGSL twin; `gpu/lut.ts` the cached 3D texture.
- `packages/filters` — one directory per filter: `index.ts` (schema + WGSL + CPU reference) and `*.test.ts` (CPU semantics). `convolution.ts` holds shared CPU convolution code and WGSL pass builders. `index.ts` at the root is the registry; `parity.browser.test.ts` checks every registered filter GPU <-> CPU at defaults and parameter extremes (images and cases in `test-utils.ts`). `fast.ts` holds the building blocks of the fast CPU paths (`convolve1dFast`, table-based `toSrgb` / `toLinear`, `mapChannels`, `mapStraight`, `sampleLutInto`); `fast.test.ts` checks every filter's `fast` against its reference. `bench/cpu-bench.ts` is the CPU bench (bundled and run in Node by `scripts/bench-cpu.mjs`). `auto.ts` `autoAdjust` (suggested white balance + levels).
- `packages/ml` — optional ML on top of core, ONNX Runtime *injected* (`OrtModule`), never imported: `sam.ts` SAM input / mask post-processing (pure TS), `segmenter.ts` `createSamSegmenter` (encode once per image, decode per click), `migan.ts` `createMiganInpainter` (object removal) and `growMask`, `depth.ts` `createDepthEstimator` (relative depth, near = 1); `models.ts` model descriptors at pinned revisions (`SLIMSAM_77`, `MIGAN`, `DEPTH_ANYTHING_V2_SMALL`) and `fetchModel` (progress, Cache API). `test/` holds the real-model integration test (`ml` Vitest project).
- `packages/node` — `renderer.ts` `createRenderer` (Node renderer: loads Dawn from the optional `webgpu` package and defines the WebGPU globals core uses, falls back to the CPU with a `reason`; `render` = file (sharp) or RGBA8 in, `applyEdit`, PNG (own encoder) or JPEG / WebP (sharp, after core's `exportSamples` flattening) out). Its tests run Dawn and sharp for real; `no-sharp.test.ts` mocks sharp away. `browser-vs-node.browser.test.ts` renders the same documents (every look, two mixed edits) on Chromium's WebGPU and, through the `renderOnDawn` Vitest command (`test/dawn-command.ts`, registered in `vitest.config.ts`, loads the sources with the Vite server's `ssrLoadModule`), on Dawn in Node, on two sample photos and a chart.
- `packages/web` — `renderer.ts` `createRenderer` (browser renderer: WebGPU through `createGpuContext`, else the CPU; `apply` / `render` (ImageData or file → encoded Blob) / `pixels` (8-bit ImageData, encoded where it renders: `applyEditPixels` in core's internal)), `worker.ts` the CPU backend's module worker (`applyEdit` with the built-in filters), `protocol.ts` its messages. `renderer.browser.test.ts` runs the worker in Chromium against WebGPU.
- `packages/konva` — `index.ts` `attachEdit` (a `Konva.Image` edited with edit documents: previews at the node's size on screen through `@rullino/web`'s `pixels`, coalesced `set`, full-resolution `export`, `detach`); `konva.browser.test.ts` runs real Konva in Chromium. `konva` is a peer dependency (dev dependency pinned).
- `packages/presets` — `bake.ts` (`bakeLut`: a pointwise chain baked into a 33³ LUT) and `looks.ts` (the looks: grade + vignette + grain, `lookSteps`, `lookLut`; as edit documents `lookEdit`, LUTs named `look:<id>` by `lookLutRef` / `resolveLookLut`); golden charts in `__snapshots__`.
- `apps/playground` — Vite site; consumes packages through their public `index.ts` only. `controls.ts` generates the parameter UI from a schema (curve params share one `curve-editor.ts` with tabs); `chain-ui.ts` is the chain state and the inspector of the selected step (description, generated controls, mask), `film-strip.ts` the chain as a strip of frames under the photo; `mask-ui.ts` the per-step mask panel and `mask-overlay.ts` the on-image handles / brush; `geometry-ui.ts` the Geometry panel, `crop-overlay.ts` / `perspective-overlay.ts` its on-image editors; `effect-browser.ts` / `effect-search.ts` the Ctrl+K effect browser; `histogram-view.ts`; `history.ts` undo/redo, `share.ts` share-link encoding, `code-export.ts` / `code-dialog.ts` "Copy as code" (the Code button: the edit document and browser / Konva / Node snippets, loaded on first use), `zoom.ts` zoom / pan / pinch, `object-select.ts` the Object mask tool (backend choice, lazy model, per-image encoding), `object-remove.ts` Remove object (lazy MI-GAN), `depth-estimate.ts` Estimate depth for the lens blur (lazy Depth Anything); `scripts/smoke.mjs` is the e2e smoke test, `scripts/smoke-ml.mjs` the Object tool's. `scripts/fetch-models.mjs` (repo root) downloads the test models.

- `apps/bench` — the comparison page (#77): `harness.ts` `runBench` (init / first run / change latency / memory / |Δ| vs the first adapter, unit-tested with fake adapters), `adapters/*` one per library (each its own chunk), `chains.ts` the chains as data, `rullino-chains.ts` as rullino steps, `tables.ts` the curve table and colour map rullino computes for the libraries that lack curves / 3D LUTs, `vite.config.ts` cross-origin isolation, library versions and `sizes.json` (gzip per adapter); `scripts/run.mjs` builds, serves and optionally runs it headless.

- `examples/` — one-file examples on the published packages (`^x.y.z` ranges, not workspace links, so StackBlitz can open them from GitHub): `konva-editor` (Konva stage + sliders + look picker + export), `node-batch` (an edit document rendered onto a folder of photos with `@rullino/node`), `worker-fallback` (`@rullino/web` with a backend menu: WebGPU, or the CPU in a worker). Not workspace members and not type-checked; `pnpm test:pack` copies each one's files next to the installed tarballs, builds it with Vite and drives it in Chromium (`node-batch`: runs the script and checks the files and sizes it writes; `worker-fallback`: forced onto the CPU backend with `?backend=cpu`).

- `docs/guides/` — docs by job (preview and export, the same edit on the server, looks in your editor, remove an object on-device, migrating from glfx.js and tui.image-editor); every `ts` block is a module of its own, compiled by `pnpm typecheck`. `docs/filters.md` and `docs/parity.md` are generated.

- `.claude/skills/` — repo skills: `add-filter` (the recipe for a new filter, tests to mutation check) and `finish-step` (verification, CLAUDE.md upkeep, PR and CI). `.claude/settings.json` enables two official plugins: `claude-md-management` and `skill-creator`.

## Rules

- **Red/green.** Write the test first, run it, see it fail, then implement. For GPU code, also check that the parity test catches a deliberately broken shader before trusting it.
- **Every filter ships with both implementations, CPU semantics tests, and is registered** in `packages/filters/src/index.ts` (which gives it the parity test). The CPU version is the specification: obvious, unoptimised, never mutates its input. Speed goes into an optional `fast` implementation next to it (tested against it by `fast.test.ts`, mutation-checked like a shader), never into the reference.
- **Every parameter has a `label`** (the registry test enforces it); the UI is generated from the schema.
- **Working space is linear, premultiplied RGBA, `rgba16float` on GPU / `Float32Array` on CPU.** sRGB exists only at the I/O edges. Filters that need straight alpha (LUTs, curves, OKLab) must un-premultiply internally.
- **Pointwise WGSL is a pure function** `fn apply(c: vec4f, p: Params) -> vec4f`; no bindings, no globals, no `Params` declaration (it is generated from the schema). This is what lets consecutive pointwise filters fuse into one shader.
- **Multipass pass WGSL** defines `fn run(xy: vec2i, p: Params) -> vec4f` and reads inputs only through the generated `load_<input>(xy)` (clamp to edge). Pass lists are static: anything that varies with params goes in uniforms, so the shader cache keys stay `filter:pass`. Iteration goes through `repeat: '<int param>'` (ping-pong on `inputs[0]`), never through a params-dependent pass list.
- **Reductions** (histograms, global statistics) use filter `buffers` (zeroed `array<atomic<u32>, N>`) and `kind: 'compute'` passes (`dispatch: 'pixels'` or `'single'`); store floats with `bitcast<u32>`.
- **Filters with hard decisions** (thresholds, comparisons) mirror the GPU's f16 intermediates in their CPU reference (round each intermediate image) and may declare a small `tolerance.outliers` fraction. Measure the actual outliers before choosing it.
- **Curve params are read in WGSL only through the generated `curve_<name>(x)`** (never index the LUT yourself): it handles the fused-stage namespacing and linear extrapolation outside [0, 1].
- **Lengths in pixels are `unit: 'px'` params**, defined at the original image's resolution; chains scale them (`setSource({ scale })`, `runChainCpu({ scale })`).
- **In filter WGSL, top-level declarations (`fn`, `const`, `struct`) start at column 0 and locals are indented.** Fusion prefixes top-level names by matching line starts; an indented top-level declaration would not be namespaced and could collide with another filter's.
- **Public API changes are deliberate**: a new export goes into the package root and into its `api.test.ts` list; plumbing other packages or tests need (shaders, packing, caches) goes into `./internal`, outside semver.
- **Library code must build with `types: ["@webgpu/types"]` only** (`tsconfig.build.json`): no Node APIs in `packages/*/src` (tests may use them).
- **Zero runtime dependencies** in `packages/*`. `@rullino/ml` takes ONNX Runtime as an argument (optional peer dependency), it never imports it.
- Parity tests feed CPU and GPU the same **float16-quantised** input, so the tolerance only covers output rounding and math differences. Use odd image sizes to exercise workgroup bounds and row padding.
- Commit small and often; run `pnpm typecheck && pnpm test:all` before pushing (and `pnpm build && pnpm test:e2e` when the playground or filter list changes). When piping their output (`| tail`), use `set -o pipefail`, or a failure slips through to the commit.
- **Workflow**: one branch and one PR per milestone step, based on `main`. Claude may merge its own PR once CI is green and no review thread is open; afterwards delete the branch and start the next one from `main`.

## Decisions

| Decision | Why |
|---|---|
| pnpm workspaces monorepo | core / filters / presets / playground version and test together; playground consumes the packages like an outside user would. |
| Vitest (not `node --test`) | One runner for Node unit tests and browser mode (Playwright), so parity tests share assertions and config. |
| WebGPU tests in headless Chromium with `--enable-unsafe-webgpu` | Hosted CI has no GPU; Chromium falls back to SwiftShader. Verified on day one because it is the riskiest piece of M0. Needs a secure context (Vitest serves from localhost). |
| `playwright` pinned to 1.56.x | Matches the Chromium pre-installed in Claude Code cloud sessions (no download). CI installs its own browser. Bump deliberately. |
| WGSL kept in TS template strings (`/* wgsl */`), not `.wgsl?raw` | Works in any bundler and in Node without a plugin; the library must not depend on Vite. |
| Own float16 conversion (`half.ts`) | `Float16Array` is not available everywhere yet (Node 22). Round-to-nearest-even, tested against known bit patterns. |
| Package `exports` point at `src/*.ts` in the workspace; the published tarball gets `dist/` through `publishConfig.exports` | No build step in the dev loop (Vite, Vitest and tsc read the sources); `pnpm pack` swaps the exports. The build is plain `tsc` (ESM + `.d.ts`, one file per module, no bundler, zero dependencies) plus `scripts/fix-imports.mjs`, because the sources use extensionless relative imports that Node ESM cannot resolve. `tsconfig.build.json` maps `@rullino/*` to the sibling `dist/*.d.ts` (so a package never compiles another's sources) and allows only `@webgpu/types`, so Node types cannot leak into library code. |
| `pnpm test:pack` (tarball contents, Node ESM import + CPU run, Vite bundle + GPU filter in Chromium) runs in the `test` job | Nothing else ever loads `dist/`: the first run failed on a wrong call in the script, but mutations that skip the import rewrite or the `files` field both fail it. `@webgpu/types` is an optional peer dependency of core (the `.d.ts` mention `GPUDevice` etc.). |
| Filter texts live in the schemas (`description`, `tryThis`, param `description`), shown by the playground and the generated reference; `registry.test.ts` requires all three on every filter | One source: changing a filter changes its explanation, and a test fails if a filter lacks one. The cost is bundle size: 18 filters added 2.3 KB gzip (~130 B each), so the filters budget went from 41500 to 48000 for all 51, and the playground's main chunk (it bundles every filter) from 68000 to 72000 (measured with all 51 described: see `pnpm size`). The effect browser and the film strip then took it to 72.8 KB, so the limit went to 76000. A consumer importing single filters pays only for those; if that ever matters, move the prose to a separate `help` module. |
| Size budget in `size-budget.json` (gzip -9 of each package's dist JS, and of the playground's main and ONNX Runtime chunks), limits ~10% above the measured sizes | Measured at M5.2: core 34.7 KB, filters 32.8 (35.9 with gradient and laplacian, 38.5 with the 0.2 effects so far); core 36.8 with `fillShape` (budget 40), playground main chunk 63.4 with the selection (budget 68), presets 2.1, ml 5.2 (6.3 with the integrity check), playground main chunk 57.8, ORT chunk 37.4. A concatenated dist is a ceiling (consumers tree-shake); the budget catches accidental bloat, and raising a limit needs a reason in the PR. |
| npm scope `@rullino/*`, `publishConfig.access: public` | The npm org exists (Free plan); scoped packages default to private, which Free cannot publish. |
| Library packages are public from `0.1.0-rc.0` (lockstep version, `scripts/set-version.mjs`); `prepublishOnly` refuses a publish from the package directory | Their `exports` point at `src/*.ts`; only the tarball made by `pnpm pack` has the dist exports, so releases publish the packed tarballs (`.github/workflows/release.yml`), never a directory. The playground stays private forever. |
| Publishing via npm trusted publishing (OIDC) from `release.yml`, on a `vX.Y.Z[-pre]` tag that is on `main`; `scripts/release-info.mjs` gates tag = version of all four packages, `-pre` publishes to the `next` dist-tag, the rest to `latest`; notes come from the CHANGELOG section | No long-lived token. Never add an `NPM_TOKEN` secret. Each package's Trusted Publisher on npmjs.com must name this exact workflow file. Re-running a half-failed release skips versions already on npm. Node 24 for npm >= 11.5.1. |
| GPU tests never skip when WebGPU is missing | A skipped parity test looks green and is indistinguishable from a deleted one. `adapter.browser.test.ts` runs first in CI and fails if `requestAdapter()` is null. |
| License: MIT | Permissive and conventional for a JS library; see `LICENSE`. |
| `noUncheckedIndexedAccess` on | Catches out-of-range reads elsewhere; in pixel loops, where the bounds are obvious, write `data[i]!`. |
| Pointwise filters declare `alpha: 'straight' \| 'premultiplied'`; core does the (un)premultiply on both CPU and GPU | One place for the alpha rules instead of every filter re-implementing them; parity tests cover both wrappers. Linear-in-colour ops (exposure, white balance, grayscale) stay premultiplied. |
| Perceptual adjustments (contrast, brightness, saturation, vibrance) in OKLab | Hue-stable and perceptually even; plan §2.3. Contrast pivots on 18% grey (L = cbrt 0.18). |
| Perceptual "levels" (invert, threshold level, posterize) in sRGB-encoded units | That is what people mean by "50%" or "invert"; mid grey stays mid grey. |
| Brightness = power curve on OKLab L, gamma = per-channel power on linear RGB | Two different tools: brightness keeps hue/chroma, gamma is the classic channel operation. |
| White balance = luminance-normalised RGB gains | Simple creative control; a proper chromatic adaptation (Bradford / CCT) can come with auto WB in tier B. |
| Enum values are passed to WGSL as the option's index (u32) | Uniforms stay 4 bytes per param; WGSL `switch` on `0u, 1u, ...` in option declaration order. |
| Playground output via `readSrgb8` + `putImageData` on a 2D canvas, not a WebGPU canvas | A WebGPU canvas loses the device in headless Chromium/SwiftShader, so direct presentation could not be tested in CI. Costs one readback per frame; revisit with M2's reduced preview. |
| Sample photos: a few public-domain / CC0 photos in `apps/playground/public/samples` (≤ 2048 px JPEG, credits in its `NOTICE.md`); generated test images kept for the smoke test, which pins one with `?sample=ramps` | Real photos make the demo meaningful; only CC0 / public-domain files, so the MIT repo needs no licence juggling (was: everything generated in code). |
| Fused shaders keyed on filter structure only; params live in a uniform block | Moving a slider re-uploads uniforms but never recompiles. |
| `runPointwise` is the one-filter case of `runFused` | One codegen path; every per-filter parity test also exercises fusion. |
| Pipeline caches each stage's output keyed on everything upstream | Changing a step recomputes from that stage on; with neighbourhood filters (next) the stages before a blur are reused. Fused GPU chains keep f32 between filters, so they are slightly *more* precise than the CPU reference applied in f16 steps would be; chain parity uses summed tolerances. |
| Linear-light area downscale for display and preview | Box filtering premultiplied linear values is the correct way to shrink; `createImageBitmap` / canvas resizes work in sRGB. Only images beyond the device's texture limit get a browser resize first. |
| Playground: display ≤ 2048 px, preview ≤ 768 px while dragging | Two Pipelines with their own caches; release re-renders at display size. Export re-runs the chain on the full-resolution texture in a throwaway Pipeline, so its intermediates do not stay in memory. |
| `multipass` filter kind = static list of named passes over textures | Covers convolutions, edges, morphology without a general graph language; each multipass filter is its own Pipeline stage, so the stages before it are reused when something after it changes. Workgroup-memory tiling is a later optimisation; correctness first. |
| Convolutions work on premultiplied linear values with clamp-to-edge | Blurring premultiplied light is physically right and avoids dark fringes at alpha edges. Sharpening touches colour only (alpha kept) and floors colour at 0. |
| Unsharp mask has no threshold (yet) | A hard threshold makes GPU (f16 intermediates) and CPU (f64) disagree on pixels near it; add a soft one later. |
| Custom kernel is always 5×5 | One shape in the schema and UI; a 3×3 kernel is the centre of the grid. |
| Canny hysteresis = fixed number of 8-connected propagation rounds (`iterations` param) | Exact GPU/CPU parity and a static pass list; enough rounds equal full hysteresis. A convergence check (atomics) can cut the passes later. |
| No ghost-zone (workgroup-memory) hysteresis | Tried: K steps per dispatch on a (16 + 2K)² block, exact parity. On SwiftShader Canny went from 2.4 s to 19.5 s (K=8) / 11.1 s (K=4): barriers and workgroup memory are very slow there and each block redoes ~4x the pixels. Kept on branch `claude/canny-ghost-zone-experiment` for a real-GPU comparison. |
| Canny thresholds on |∇|/4 of sRGB-encoded luminance, 45° directions without atan2 | Perceptual edges; comparing |gy| with tan(22.5°)|gx| gives identical sectors on CPU and GPU. NMS uses `>=` on one side and `>` on the other so a symmetric ridge stays one pixel wide. |
| Parity suite runs every filter on random noise *and* a ring image with fading contrast | Noise never produces connected weak edges or smooth gradients; a "hysteresis runs once" mutation passed on noise alone. |
| Reductions via storage buffers + compute passes inside the multipass model | Otsu needs histogram -> threshold -> apply; keeping it inside one filter means the Pipeline needs no new stage type. Buffers are recreated per run (WebGPU zero-fills new buffers). |
| Explicit bind group layouts for multipass passes | `layout: 'auto'` drops bindings the shader never reads; an input declared but unused then made the bind group invalid. |
| Otsu on a 256-bin histogram of perceptual luminance of the straight colour, transparent pixels skipped | Matches `threshold`'s units; transparent areas would otherwise drag the threshold to black. Ties keep the first maximum on both sides. |
| Adaptive threshold = luminance > Gaussian local mean − C (OpenCV's ADAPTIVE_THRESH_GAUSSIAN_C) | Familiar semantics; σ is a px param so it scales with previews. |
| Texture pool (`createWorkingTexture` / `releaseTexture`) | New textures are lazily zero-filled; with one per pass, allocation dominated long filters (Canny hysteresis 5.8 s -> 2.5 s on SwiftShader with ping-pong alone). Reuse is safe because the queue runs in order and every pass overwrites every pixel. Capped at 16 free textures per device. |
| Gaussian weights by recurrence, taps summed in symmetric pairs | One `exp()` per tap was a large share of blur cost (~-20 to -25%); f32 drift over 150 taps stays far inside the parity tolerance. |
| Benchmarks are a separate Vitest project (`pnpm bench`), not tests | Timing assertions would be flaky on shared runners; results are written to `packages/filters/bench/results.txt` because browser console output is not forwarded. |
| Curves = Fritsch-Carlson monotone cubic sampled to 256 f32 values, linear interpolation, linear extrapolation outside [0, 1] | No overshoot between points; CPU and GPU read the very same LUT; identity curves keep HDR. 1 KB of uniforms per curve. |
| Generated `curve_<name>()` samplers read the global uniform | Pointwise `apply()` gets `Params` by value, which WGSL cannot index dynamically; the sampler is emitted with the filter's code so fusion namespaces it. |
| Curves filter in sRGB-encoded units, RGB curve then channel curves | Matches how photo editors present curves. |
| Levels clip to the output range, HDR included | Classic levels semantics; an unclipped top made narrow input ranges overflow float16. Minimum input range is one 8-bit step. |
| Black point and shadows/highlights on OKLab lightness, global | Hue/chroma stay put. Local (detail-preserving) shadows/highlights is tier B "brilliance". |
| `lut` param: domain (32 B) in the uniform block, table in an `rgba32float` 3D texture cached per `Lut` object and device | Uniforms stay small; one upload per LUT. Stage keys use the LUT's identity (`objectKey`), never its data, so LUTs must be treated as immutable. Multipass filters only (pointwise fusion has no bindings). |
| Manual trilinear LUT interpolation with `textureLoad`, not a hardware sampler | `rgba32float` is not filterable without the optional `float32-filterable` feature, and hardware filtering uses low-precision weights; the manual version matches `applyLutCpu` step for step. |
| `applyLut` works on straight sRGB-encoded colour; intensity blends in the same units | That is what `.cube` / Hald LUTs are authored for; intensity 0 is an exact no-op even for HDR values the LUT would clamp. |
| Vignette darkens by multiplying linear light, lightens towards white; smoothstep on a corner-normalised distance | Multiplying light is what lens falloff does; normalising so corners are 1 keeps `midpoint` meaningful at any aspect ratio and roundness. |

## Traps

Things that already bit us. Add new ones as they come up.

- **A texture must have exactly one owner: pooled (`releaseTexture`) or destroyed, never both.** The playground gave the previous image's raw textures to the pool (it judged ownership against the *new* image) and then destroyed them; the pool handed out destroyed textures and every later frame failed with "Destroyed texture used in a submit". Browsers log such errors as warnings, so it went unseen until `createGpuContext({ onError })` made them `console.error` and the e2e smoke test (which fails on console errors) caught it. Track ownership explicitly (a Set of the textures a renderer made), not by comparison.

- **`uncapturederror` events reach a listener only after a round trip to the GPU process** in headless Chromium: a test that triggers an error and waits on a timer sees nothing; `await device.queue.onSubmittedWorkDone()` first (or an error scope's `popErrorScope()`). An adapter can create one device only ("adapter is consumed"): request a new adapter per device.

- **Changing a dependency field of a `package.json` (also a peer dependency) needs `pnpm install` and the lockfile in the commit**: CI installs with `--frozen-lockfile` and fails both jobs in seconds otherwise.
- **A dynamic `import()` of a package the entry already imports statically can deadlock** when the bundler puts both in one chunk and the entry uses top-level `await` (the import waits for the entry to finish): import statically (it bit `scripts/pack-smoke.mjs`).

- **Extensionless relative imports do not load under Node ESM**: `dist/` only works after `scripts/fix-imports.mjs` rewrites them (`./color` -> `./color.js`, `./gpu` -> `./gpu/index.js`); `pnpm test:pack` is what notices. New import forms (e.g. `import x from './x.json'`) need the script to know them.
- **`runChainCpu(steps, src)`** takes the steps first.

- **`navigator.gpu` needs a secure context.** In Chromium, `about:blank` and plain-HTTP non-localhost pages have no `navigator.gpu` even with `--enable-unsafe-webgpu`. Vitest serves from localhost, which counts as secure.
- **Headless Chromium needs `--enable-unsafe-webgpu`** to expose WebGPU; without it `requestAdapter()` returns null. Set in `vitest.config.ts`.
- **`copyTextureToBuffer` needs `bytesPerRow` to be a multiple of 256**; `writeTexture` does not. `readImage` pads and un-pads rows; test with odd widths.
- **Compute dispatch rounds up to whole workgroups**, so shaders must bounds-check `global_invocation_id` against `textureDimensions`. Test with sizes that are not multiples of 8.
- **Parity tests must quantise the input to float16 first**, otherwise the tolerance has to absorb input rounding too and stops catching real bugs.
- **Check that a parity test can fail**: break the shader slightly (e.g. scale by 1.002) and confirm it goes red before trusting it.
- **Configuring a WebGPU canvas in headless Chromium (SwiftShader) loses the device** ("A valid external Instance reference no longer exists"), with or without `STORAGE_BINDING`, old or new headless. Anything a test must check goes through textures and readback.
- **Integer downscale ratios hide weighting bugs** (every coverage weight is 1). Test resizes with fractional ratios.
- **`layout: 'auto'` silently drops unused bindings**, so binding an unused input fails validation with an empty output and no exception. `cachedPipeline` takes explicit layout entries; multipass passes always use them.
- **A failed pipeline/bind group shows up as an all-zero output** (alpha 0), not as an exception. When a GPU test gets zeros, suspect validation first.
- **Only `run()` receives `p`**: helper functions in pass WGSL must read the global `params` uniform (shared pass builders take `params.<name>` expressions).
- **WGSL cannot dynamically index an array held by value** (e.g. the `p` parameter). Index through the global `params` uniform instead (`params.kernel[n / 4][n % 4]`).
- **Multi-pass GPU filters round intermediates to f16**; anything that amplifies a difference (unsharp `amount`) amplifies that rounding, so its tolerance must grow with the gain.
- **Symmetric test kernels hide transposed indexing**: parity tests use an asymmetric kernel.
- **Workgroup memory and barriers are very slow on SwiftShader**: an "optimisation" built on them can be a large regression in CI and cloud sessions. Measure with `pnpm bench` before keeping it.
- **Hard contrast switches make T-junctions**, which non-maximum suppression breaks; Canny test images that need connected weak edges must fade contrast gradually.
- **Random-noise test images miss structure-dependent bugs** (hysteresis, gradient direction). Mutation-check new filters against the ring image too.
- **Do not judge the playground from a screenshot taken after a fixed timeout**: first-use shader compilation on SwiftShader takes seconds. Wait for `#status[data-frame]` to advance, as `scripts/smoke.mjs` does.
- **Resizing a canvas clears it.** The after canvas is resized only when a new frame is drawn, so the previous image stays up while a new one loads.
- **A filter's `id` is not unique**: two filter objects can share it. Anything cached per filter (shaders, Pipeline stages) keys on `objectKey(filter)` too.
- **Async loads in the playground must not overlap**: each destroys the previous textures. `loadImage` queues them and skips superseded ones; swap Pipeline sources before destroying old textures.
- **Integer-like object keys are reordered by JS** (`{ '5': …, '3': … }` iterates '3' first), so enum option keys must not be integer-like.
- **Allocating textures is expensive** (lazy zero-fill): get working textures from `createWorkingTexture` and give intermediates back with `releaseTexture`, never create one per iteration.
- **Browser-mode `console.log` does not reach the terminal** here; use `commands.writeFile` from `vitest/browser` (paths are relative to the repo root).
- **`sampleCurve` caches its LUT per points array**: never mutate a points array after sampling it (the curve editor samples a copy).
- **The registry parity test varies one param at a time**: interactions between params (curve order, combined settings) need a dedicated GPU test. Params with no effect at their partners' defaults (colour grading's colours and balance at strength 0) are not tested at all there: a balance mutation passed.
- **WGSL rejects mixing `&` / `|` with comparisons without parentheses** (`a <= k & k < b` does not compile): write `(a <= k) & (k < b)`. Like any shader error, it shows up as an all-zero output.
- **WGSL `round()` is round-half-to-even, `Math.round` is half-up.** Use `floor(x + 0.5)` on both sides when parity matters.
- **OKLab round trips leave float noise** (~1e-26 instead of 0): assert with a small epsilon, not `>= 0`.
- **Uint8ClampedArray needs `<ArrayBuffer>`** for `new ImageData(...)` under TS's typed-array generics; `readSrgb8` returns that type.
- **A LUT cannot follow the sRGB curve's kink at 0**: grades that push colours out of gamut (saturation boosts) interpolate poorly next to the gamut edge. Compare baked vs live chains as displayed (clipped) and on average, not by the worst pixel alone.
- **`convertToBlob` silently falls back to PNG** for a type the browser cannot encode (e.g. WebP in some browsers); `encodeSamples` checks `blob.type` and throws.
- **Replacing an SVG element while it is dragged drops its pointer capture**: the mask overlay updates attributes and rebuilds elements only when the mask kind changes.
- **UI modules that keep their own copy of shared state go stale** once a second editor exists (panel vs on-image handles): read the current state through a getter.
- **A mask outlives image changes** (normalised coordinates), so a raster can have another image's proportions: refit it (`fitRaster` / `resampleRaster`) before tools that need the image at the raster's size.
- **Playwright's `mouse.click` has no `modifiers` option** (only `page.click` does): hold keys with `keyboard.down` / `up`.
- **`pnpm bench` broke silently once** (a mask-aware filter was registered) when it was not in CI; CI now runs it, without asserting timings.
- **An e2e check can pass without exercising the path it is about**: e.g. preview-only reframing never runs on images ≤ 768 px (preview and display are the same texture). Mutation-check new smoke checks too.
- **Playwright clicks are too slow to provoke async races**: dispatch the events in one `page.$eval` task (as the wand-race check does).
- **A new frame is not proof the latest state is shown**: changes made while a frame is in flight coalesce into the next one. E2E checks of geometry wait for the expected result (sizes, pixels), not for a frame count.
- **Handles on the image edge are half clipped** by an `overflow: hidden` overlay: the crop / perspective overlay uses `overflow: visible`.
- **Playwright version must match the installed Chromium build** in cloud sessions (1.56.x ↔ chromium-1194), or it tries to download a browser. Since late Oct 2026 the cloud image ships chromium-1243 (and a new path layout): until the pin is bumped, shim it locally with `mkdir -p /opt/pw-browsers/chromium_headless_shell-1194/chrome-linux && touch /opt/pw-browsers/chromium_headless_shell-1194/INSTALLATION_COMPLETE && ln -s /opt/pw-browsers/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell /opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` (all GPU tests pass with it). CI installs its own browser and is unaffected.
- **Synthetic `PointerEvent`s cannot be captured**: `setPointerCapture` throws "No active pointer". Dispatch fake touches where no handler captures (the smoke test pinches on `#stage`).
- **WGSL shift amounts must be `u32`** (`4 << (2 * level)` with an `i32` level does not compile): `4 << u32(2 * level)`. As always, an all-zero output.
- **A generous `outliers` allowance hides subtle mutations**: dither at 1% let a shifted threshold (~0.6% flips) pass 14 of 16 cases. Measure with `outliers: 0` first, then allow just above what you measured.
- **`copyExternalImageToTexture` from a `<canvas>`, `<img>` or `VideoFrame` loses the device on SwiftShader** ("A valid external Instance reference no longer exists"), like configuring a WebGPU canvas. Tests import through `ImageBitmap` / `ImageData`.
- **ONNX Runtime's WebGPU backend refuses concurrent session creation** ("another WebGPU EP inference session is being created"): create sessions one after the other (the fake ORT in `segmenter.test.ts` enforces it).
- **ORT's WebGPU EP on SwiftShader is ~25× slower than WASM** (SlimSAM encode 480 s vs 19 s): never benchmark ML on WebGPU in CI or cloud sessions; the app picks WASM on software adapters.
- **A SAM click on a uniform background is ambiguous**: the best-scored mask is often the whole image. Test point prompts on objects, and labels with positive + negative pairs.
- **Node's `fetch` ignores `HTTPS_PROXY`** in CI / cloud sessions: scripts that download (models) use `curl`.
- **MI-GAN's mask is inverted** (255 = known, 0 = hole), and the other ONNX file in the repo (`migan.onnx`) is the same signature; try both conventions on a rectangle before trusting a wrapper (outside the hole must come back unchanged).
- **A frame advancing is not proof that a later state is shown** (again): the Remove object e2e check polls for the changed pixels instead of waiting for `frame > n`; the Object selection's own render had already advanced it.
- **ORT / onnxruntime need external-data files next to the model under their original name** (`model.onnx_data` for the Depth Anything 3 export); loading the `.onnx` alone from another folder fails with "External data path does not exist". Not an issue for the int8 DA2 file (single file).
- **Param names become fields of the generated WGSL `Params` struct**, so WGSL reserved words (`operator`, `filter`, `target`...) fail to compile (all-zero output): the registry parity test notices. And when mutation-checking, a `sed` that matches both the shader and the CPU reference changes nothing: anchor it on the WGSL's indentation.
- **`npm publish` from a package directory ships `exports` pointing at `src/*.ts`** (the dist exports exist only in the `pnpm pack` tarball). `prepublishOnly` refuses it; the release workflow publishes tarballs, which does not run that hook.
- **`npm publish dir/file.tgz` reads a path with a slash and no `./` as a GitHub shorthand (`owner/repo`)** and tries to `git clone` it ("Permission denied (publickey)"). The release workflow uses `./tarballs/...`; `pnpm test:pack` runs `npm publish --dry-run` on each tarball in the same form. The first release attempt (`v0.1.0-rc.0`, never published) failed on this: a tag cannot be reused once the workflow it runs is wrong, so the fix went out as `rc.1`.
- **A cloud session cannot push tags** (the git proxy only accepts the session's branch: "remote end hung up"), so the maintainer pushes release tags (`git tag vX.Y.Z origin/main && git push origin vX.Y.Z`). Never create the GitHub release from the web UI instead: `release.yml` creates it from the CHANGELOG and fails if it already exists.
- **Dawn's `webgpu` package needs a Vulkan driver on Linux**: without one `requestAdapter()` returns null ("vkCreateInstance: Found no drivers"). `apt install mesa-vulkan-drivers` (lavapipe) fixes it; the loader finds it without `VK_ICD_FILENAMES` once installed. Its `postinstall` script only matters on macOS (quarantine flag), so pnpm's blocked build scripts are fine on Linux.
- **Dawn on lavapipe compiles every shader with LLVM, and a fresh CI runner has an empty Mesa shader cache**: the first Dawn render took 3.8 s in `pnpm test` (0.9 s in `test:coverage` right after, cache warm) and once went over Vitest's 5 s default in the release job. Locally the cache is warm and the same test takes 0.2 s, so it never shows here (`MESA_SHADER_CACHE_DISABLE=true` gets closer). Dawn tests declare `{ timeout: 60_000 }`; CI steps have `timeout-minutes` so a real hang fails in minutes (#100).
- **A coverage threshold failure can be a crashed test file, not missing tests.** `pnpm test:coverage` failed once in CI (function coverage of `packages/*/src` 98.95% against 99%) on a PR that touched no package source; the log showed `Worker exited unexpectedly with signal SIGABRT ... while running test file packages/node/src/renderer.test.ts` (Dawn's native code, reported by Vitest as an unhandled error) and no `✓` line for that file, so its coverage was lost (`createRenderer`'s `destroy()` came out uncovered) and the threshold, which sits at the measured value, tipped. Re-running the job passed; the crash did not reproduce in 45 local runs (alone, 4 in parallel, `MESA_SHADER_CACHE_DISABLE=true`). When coverage dips on a PR that cannot have caused it, grep the log for `SIGABRT` / `Unhandled` before touching tests or thresholds; to find the flipped function, download the failed run's `coverage` artifact (`gh api repos/Stocastico/rullino/actions/artifacts/<id>/zip`) and diff its `coverage-summary.json` per file against a local run.

- **The parity tests are calibrated on software GPUs (SwiftShader in CI), not on real ones.** The first run on real hardware (RTX 40, Chrome on Windows, 30 Oct) passed 911 of 936 browser tests; the 25 failures were `canny` (exact hysteresis, hard decisions), `inpaint` / `sketch` / `kuwahara` (small errors amplified by iterations, pow and division, 0.004–0.015 against tolerances of 0.002–0.006) and the hardware sRGB decode of 8-bit uploads (~0.4 of an 8-bit step, tolerance 2^-9), plus the browser-vs-Node guard "results must not be bit-identical", which cannot hold when both sides use the same GPU and driver (now checked between software renderers only). Do not widen a published tolerance to make a local run green: run `pnpm report:parity` on the hardware, and decide per filter from the numbers (tolerance with a hardware note, reference change, or outliers for hard decisions).
- **Scripts must work on Windows too**: never turn `import.meta.url` into a path with `new URL(...).pathname` (it gives `/C:/Users/...`, and `join` made `C:\C:\...`): use `fileURLToPath(new URL(...))`. And `pnpm`, `npm` and `node_modules/.bin/*` are `.cmd` shims there, so `execFileSync` needs `shell: true` on `win32`, and package scripts must not use `rm`, `cp` or `cat` (cmd has none): `node scripts/fs.mjs rm|cp|cat`. Also on Windows, Playwright's bundled headless Chromium finds no GPU adapter (`requestAdapter()` is null, so the whole GPU suite fails) while the installed Google Chrome does: `scripts/browser-launch.mjs` picks the `chrome` channel there (override with `RULLINO_BROWSER_CHANNEL=chrome|chromium|msedge|bundled`; every browser-launching script and `vitest.config.ts` use it), and `--enable-features=Vulkan` is Linux-only. CI and the cloud sessions are Linux, so this only shows on a maintainer's Windows machine (`pnpm typecheck` failed there on the first try, 30 Oct); the Windows fixes are untested in CI.
- **StackBlitz (WebContainers) cannot load Vite 8's native Rolldown binding** ("Cannot find native binding"): examples pin `vite@^7` (Rollup + esbuild), which StackBlitz runs; the repo itself stays on Vite 8. `pnpm test:pack` builds the examples with the repo's Vite, so it cannot notice this: open the StackBlitz link after changing an example's dependencies.
- **TypeDoc renders the root README** (`pnpm build:docs`, warnings are errors): a relative link to a directory (`./examples/x`) fails it, since TypeDoc copies only linked files. Link directories by their GitHub URL; run `pnpm build:docs` when a README changes.
- **`vitest.config.ts` is loaded by plain Node**, which cannot import the workspace TS sources (extensionless imports): browser commands that need the packages load them with `ctx.project.vite.ssrLoadModule('/packages/…/src/index.ts')` and keep only type imports at the top.
- **Do not time small functions under Vitest**: its module runner turns calls to imported functions into getter calls (4–5× slower per call); `pnpm bench:cpu` bundles first. Allocating a 12 MP `Float32Array` (192 MB) costs 0.15–1.1 s in cloud containers (page faults, GC): avoid needless full-image copies.
- **`x ** 3` is a `pow()` call in V8**: write `x * x * x` in pixel loops (it was a third of the OKLab filters' time).
- **Functions cannot be posted to a Worker** (filters, LUT resolvers): resolve on the main thread and send data, or keep that work on the main thread. And Vite's dev server pre-bundles dependencies with esbuild, which breaks `new URL('./worker.js', import.meta.url)` inside them: apps exclude `@rullino/web` from `optimizeDeps` (production builds are fine).
- **Photon 0.3.3's noise functions (`add_noise_rand`, `pink_noise`) trap in WASM** ("unreachable", random source unavailable), and the trap leaves the image borrowed ("attempted to take ownership of Rust value while it was borrowed" on `free()`): the bench skips Photon's grain.
- **wasm-vips: `extractBand` makes a 'multiband' image**, from which colour operations (sharpen's LabS round trip, `colourspace`) have no route: set `interpretation: srgb` with `copy()` first. **pixi-filters' `ConvolutionFilter` `width` / `height` are the image's** (texel size), not the kernel's: 1 × 1 gave a garbage picture (\|Δ\| 118).
- **`performance.measureUserAgentSpecificMemory` throws in headless Chromium** even when cross-origin isolated: catch it and fall back to `performance.memory` (JS heap only, coarse).
- **An e2e check on a two-stage effect must wait for both effects** (lens blur: background blurred *and* the picked focus applied); the first stage alone already satisfies half of the condition.
